# RF500 Raspberry Pi 5 kedua (100.94.161.96): paket siap, instalasi tertahan SSH

**Tanggal:** 18 November 2026 WIB.
**Branch:** `wahyu`.
**Target:** Raspberry Pi Tailscale **`100.94.161.96`**, hostname
Tailscale `raspberrypi`, terhubung lewat USB ke **board utama
E-Nose COM5** yang sebelumnya di-flash RF30 35.770 byte dan
boot `FW_HELLO` PASS.

## Hasil pemeriksaan langsung

- Windows tidak lagi mendeteksi COM5; pengguna telah
  memindahkan USB Type-B ATmega2560 dari laptop ke Pi kedua.
- `tailscale status` mengidentifikasi `100.94.161.96`
  sebagai node Linux `raspberrypi` (akun Tailscale
  yang sama dengan node `enose-pi5` `100.103.211.125`).
- `tailscale ping` merespons dari
  `raspberrypi (100.94.161.96)` melalui DERP(sin).
  Konektivitas Tailscale **PASS**, tidak sama dengan
  izin login SSH.
- SSH dengan `BatchMode=yes` ke
  `enose-v3@100.94.161.96`,
  `pi@100.94.161.96` dan
  `wahyu@100.94.161.96` ditolak:
  **`Permission denied (publickey,password)`**.
- Probing menegaskan OpenSSH server bisa dihubungi
  dan menawarkan autentikasi publickey/password,
  tetapi laptop tidak memiliki kredensial autentikasi
  terpasang untuk akun yang dicoba.
- SSH ke Pi pertama juga meminta verifikasi
  akun Tailscale yang baru pada sesi ini; **tidak
  ada perubahan pada Pi pertama**.
- Laptop Windows tidak memiliki salinan
  `final_model.joblib` dan `final_model_info.json`
  pada workspace `D:\ENOSE`. Model asli
  sebelumnya tercatat pada staging Pi pertama,
  tetapi belum bisa diekspor pada sesi ini.

**Tidak ada file yang dipasang, dependensi terinstal,
cron berubah, atau port serial dibuka di Pi kedua.**
Tidak ada upload ulang ATmega, perubahan HMI/EEPROM,
atau AI Test dijalankan.

## Program yang disiapkan untuk deployment aman

Program RF500 permanen sebelumnya dapat
memproses 900 sampel/30 siklus,
mengirim `#rf30:<token>:<light|medium|dark>;`
setelah validasi lengkap, menunggu
`AI_RESULT_ACK`, dan menyimpan
data raw NDJSON dan JSON hasil.

**Perbedaan identitas hardware:** Pi pertama
memakai FT232RL Linux `A10KMZQJ`
(Windows `A10KMZQJA`), sedangkan board
utama COM5 memiliki serial Windows
`A10KMM3SA` (Linux **diperkirakan**
`A10KMM3S`; perlu dilihat langsung setelah SSH berhasil).
Kode sekarang memuat allowlist dua FTDI spesifik,
tidak menerima port `/dev/ttyUSB0` generik.

File baru dan yang diperbarui:

- `scripts/rf500_pi_persistent_listener.py`:
  allowlist identitas Pi kedua dengan port USB `by-id`
  yang spesifik; tetap kompatibel dengan default
  Pi pertama.
- `scripts/rf500_pi_verify_staged_bridge.py`:
  mendukung `--serial-live` untuk pemeriksaan port
  Pi kedua tanpa mengirim perintah atau deserialisasi model.
- `scripts/test_rf500_pi_persistent_listener.py`:
  pengujian positif FTDI kedua dan penolakan port generik.
- `scripts/pi_rf500_com5_second/boot_supervisor.sh`:
  autostart singleton `flock`, reconnect backoff,
  port FT232RL khusus COM5, data recording privat.
- `scripts/pi_rf500_com5_second/installer.py`:
  `--check`, `--install`, `--start`; memverifikasi
  Tailscale IP `100.94.161.96`, user bukan root,
  `udevadm` vendor/product/serial,
  izin UART, catu daya Pi `throttled=0x0`,
  SHA model, metadata, versi library dan
  kecocokan API bridge sebelum mengaktifkan listener.
- `scripts/pi_rf500_com5_second/deploy_from_windows.ps1`:
  transfer SCP interaktif setelah SSH bisa diakses,
  setup Python venv + dependensi, registrasi cron,
  dan start hanya setelah seluruh pemeriksaan PASS.
- `scripts/pi_rf500_com5_second/README.md`:
  instruksi instalasi dan keamanan.

**Checksum wajib model RF500 asli:**
`b2b6e8d8ff03e92c695c1b0b55a8c06ea9d4178249c9ce012203e602ff1bcf5d`.
Tidak dilakukan retraining atau pembuatan model
pengganti; model harus disalin utuh dari Pi pertama.

## Langkah agar selesai

1. Operator pastikan username **akun Linux di Pi kedua**
   dengan `whoami` pada konsol Pi, bukan hostname
   Tailscale `raspberrypi`.
2. Buka akses SSH sah (password interaktif atau
   public key milik laptop pada akun tersebut).
   Jangan membagikan password melalui chat atau Git.
3. Salin `final_model.joblib` dan
   `final_model_info.json` asli dari Pi pertama
   ke direktori privat Windows; verifikasi SHA.
4. Jalankan `scripts/pi_rf500_com5_second/deploy_from_windows.ps1`
   dengan username, jalur model, jalur metadata,
   dan `-EnableAutostart`. Script sendiri berhenti
   bila identitas perangkat/FTDI/hash tidak cocok.
5. Setelah log Pi kedua menampilkan
   `RF500_PERSISTENT_READY`, baru operator boleh
   menekan Start AI Test di Nextion; periksa
   900 sampel, hasil dan ACK fisik.
